Wispstat docs

Install

Deploy the Worker (README Deploy button or npm run setup), claim with SETUP_TOKEN, then add a site with one domain root and paste the tracker on hosts you want measured.

  • 01
    Create the site Overview → Add a site. One domain (e.g. example.com) — that host and all subdomains under it.
  • 02
    Paste the snippet From Settings or the create response. Before </body> is fine. 
    <script defer
  src="https://YOUR_WORKER/ws.js"
  data-site="s_yourSiteIdHere"></script>
  • 03
    Confirm Live Open the site → Live. You should see pageviews after a hit.

data-site is public HTML. It is an identifier, not a secret.

What logs by default

Pageviews plus light auto-events. Disable autos with data-auto-events="false".

  • Pageview on load (unless data-auto="false")
  • SPA route changes via data-spa="auto"
  • Outbound · downloads · form submit (never field values)
  • Heat + scroll depth (off with data-heatmap="false")
  • Signup / purchase / custom goals — fire wispstat('event', …) yourself

Optional: data-respect-dnt, data-exclude, data-mask, data-hash-mode, data-file-types.

Attribution

First pageview of a load captures utm_*, or ref/via, plus external referrer. That becomes same-day first-touch. CRM handoff: wispstat('attribution').

Custom events

Names ≤64 chars, charset [a-z0-9_:.-]. Pair with a Goal of kind event for conversion rates.

  • wispstat('pageview') Manual pageview Useful if auto pageviews are off.
  • wispstat('event', 'signup') Named event Pair with a Goal for conversion rates.
  • wispstat('event', 'purchase', { value: 49.9 }) Event + value Revenue in the site currency.

MCP

Agents talk to your Worker through a thin stdio MCP server in mcp/ — read API key only. No Slack digest, no Firebase.

  • 01
    Create a read API key Site → Settings → API keys. Empty origins = any. Prefer a read key for agents.
  • 02
    Install MCP deps cd mcp && npm install
  • 03
    Point your MCP client Cursor (or any stdio MCP host) example: 
    {
  "mcpServers": {
    "wispstat": {
      "command": "node",
      "args": ["/ABS/PATH/heyeddi-wispstat/mcp/src/index.js"],
      "env": {
        "WISPSTAT_BASE_URL": "https://YOUR_WORKER",
        "WISPSTAT_API_KEY": "wsk_s_…_…"
      }
    }
  }
}

Tools:

  • wispstat_budget — today’s write/request budget estimate
  • wispstat_summary — site KPIs for a range
  • wispstat_sources — channels / sources
  • wispstat_live — last ~30 minutes
  • wispstat_visits — filtered same-day journeys
  • wispstat_visit_timeline — one visitor-hash timeline
  • wispstat_heatmap — aggregate click grid + scroll depth

site_id is optional when the key embeds it (wsk_<siteId>_…). Details: mcp/README.md in the repo. Keep API keys out of git.

Share with a client

Site → Settings → Share with a client. Read-only summary via link or iframe. No login for them. Treat the URL like a password; revoke when done.

Security

  • Visitors: no cookies in default mode; daily hashed IDs; one domain root + subdomains.
  • Forms: submit events never include field values.
  • You: email/password on your Worker; keep SETUP_TOKEN private.
  • Clients: share links only see that site’s rolled-up numbers.

Found a bug in Wispstat? Report it privately to security@heyeddi.com — do not post exploit details in public issues. Include impact and repro on a throwaway Worker; redact tokens. Full policy: SECURITY.md (secure reporting steps + self-host checklist).

Data budget

Overview estimates Cloudflare Free usage today (writes and requests vs ~100k/day caps). Counts rise with real pageviews and events only.
